# 递归

## 从最优化问题到递归

[[贪心算法]]失效的一个很大原因在于它明显的局限性：它几乎只考虑局部最优解。因此在绝大多数情况下，它不能得到整体最优解，但它的解是最优解的一个很好近似。

同时，也是所有讨论最优化问题的核心基础。既然无法通过贪心算法达到整体最优，可以换一个思路，将问题扩展到递归问题上。

## 最优化问题的本质

所谓最优化问题，就是在某些约束条件下，决定可选择的变量应该取何值，使所选定的目标函数达到最优的问题。

从数学角度来说，最优化方法是一种求极值的方法，即在一组约束为等式或不等式的条件下，使系统的目标函数达到极值，即最大值或最小值。将贪心算法中的硬币找零问题用函数表示就是：

$$f(x_0, x_1) = x_0 + x_1$$

但是这个函数目前没有任何限制，根据要求需要对其进行约束，使得 5 元硬币和 3 元硬币的面值总和为 `y`：

$$5x_0 + 3x_1 = y$$

当满足这个约束条件后，求解函数中的变量 $x_0$ 和 $x_1$，使目标函数 $f(x_0, x_1)$ 的取值最小：

$$arg min_{(x0, x1)∈S}(x_0 + x_1)$$

由于 $(x_0, x_1)$ 都是离散的值，因此所有满足上述约束条件 $S$ 的组合，就是最终所求的集合。而最优化问题的本质就是从这些组合中找到一个组合使得 $x_0 + x_1$ 的值最小。离散型的最优化问题就是求所有满足条件的组合里找出最优解的组合。

## 枚举与递归 最优组合的求解策略

枚举本身很简单，就是把所有组合都遍历一遍即可。而**递归**正是得到这些组合的方法。

### 斐波那契数列示例

$$
F(n) = 
\begin{cases}
0, n = 0 \\
1, n = 1 \\
F(n - 1) + F(n - 2), n > 1
\end{cases}
$$

```java
int Fibonacci(int n) {
  if (n == 0 || n == 1) { return n; }
  if (n > 1) { return Fibonacci(n - 1) + Fibonacci(n - 2); }
  return 0;
}
```

递归形式的求解几乎就是简单地把题设中的函数表达式照搬下来，因此从数学意义上讲，递归更加直观且易于理解。

**递归**：作为一个算法解决方案，它采用了 *深度优先搜索* 的策略，且搜索所有可能的组合，并得到最优解的最优化问题。如果在每个节点上加上当前这个节点求得的组合结果，就可以用递归树来表示**求解的组合空间**。

#### 数组方式

#### 哈希表方式

如果存储的状态不能直接通过索引找到需要的值，则可以考虑使用哈希表来存储中间状态。

```java
int fibonacci(int n, int[] memo) {
  if (n == 0 || n == 1) { return n; }
  if (memo[n] != 0) { return memo[n]; }
  if (n > 1) {
    memo[n] = fibonacci(n - 1, memo) + fibonacci(n - 2, memo);
    return memo[n];
  }
  return 0;
}

int fibanacciAdvance(int n) {
  int[] memo = new int[n + 1];
  return fibonacci(n, memo);
}
```

通过这种方式，大幅缩减了算法的计算量，由于不存在冗余计算，子问题的时间复杂度为 $O(n)$，再考虑求解一个子问题的复杂度，没有计算，因此是 $O(1)$，综上该算法的时间复杂度是 $O(n)$。

将之前的硬币问题转化为函数：

$$
F(x) =
\begin{cases}
min(f(x - c) + 1), x > 0, f(x - c) != -1, c∈C \\
0, x = 0 \\
-1, x < 0 \\
\end{cases}
$$

所以需要一个集合来存储所有 $F(x)$ 的结果，以此来减少计算步骤，最终将指数级 $O(2^n)$ 时间复杂度的问题进行了简化。

针对如下形式的问题：

> 当目标为 $x$，其中 $x$ 可能是一个任意长度的向量，目标可能包含多个元素，求最优解 $F(x)$

先定义数值函数 $G(t)$，如果求最小值，那么 $G$ 是 $min$，如果求最大值，那么 $G$ 就是 $max$。此外，通过当前的问题获得后续的一系列子问题，假定当前得到子问题的参数为 $c$，得到后续子问题的函数是 $S(x, c)$。接着定义一个函数 $V(x, c)$ 来聚合当前参数 $c$ 和当前子问题的结果。最后定义每一步如何与子问题进行叠加，定义叠加函数 $H(x)$。最终得到求解公式：

$$F(x) = H(G(V(F(S(x, c)), c)))$$

### 弊端

memo 备忘录的大小会随着 $x$ 的变大而变得非常巨大，导致的结果就是会占据大量的内存存储空间，并且很多结果其实是不会被求解的，存在很多"存储空洞"。此外目标结果 $x$ 是向量的情况下，memo 会随着向量维度一起提升。
