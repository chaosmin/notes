## 动态规划

### 动态规划问题的三个特征

- **重叠子问题**：在穷举的过程中（比如通过递归），存在重复计算的现象；
- **无后效性**：子问题之间的依赖是单向性的，某阶段状态一旦确定，就不受后续决策的影响；
- **最优子结构**：子问题之间必须相互独立，或者说后续的计算可以通过前面的状态推导出来。
  - 比如需要以最低的价格购买5斤苹果和3斤香蕉，当这两种水果的促销价格相互独立、互不影响，只需直接购买促销价便可以享受最低价格，此时符合最优子结构。当有条件说两种水果的折扣不能同时享用，子问题并不独立时，苹果和香蕉的折扣架构无法同时达到最优，这时最优子结构被破坏。

### 使用动态规划求解

- 任何穷举算法（包括递归）都需要一个终止条件，在动态规划中，称其为**初始化状态**。
- 接着找出子问题与原问题之间会发生变化的变量，这个变量将其称之为**状态参数**。
- 在动态规划中，这个状态会不断逼近初始化状态，而这个不断逼近的过程，叫做**状态转移**。在确定了状态之后，我们需要通过操作来改变状态，来使其不断逼近初始化状态，在动态规划中，将其称之为**决策**。

### 状态转移方程

初始化状态 -> 确定状态参数 -> 设计决策

针对硬币问题，初始化状态即当剩余的金额为 $0$ 时，因为此时不需要任何硬币就可以凑出目标金额；原问题制定了硬币的面值且没有限定硬币的数量，唯一的状态参数为目标兑换金额 $k$；而决策就是不断挑一枚硬币来凑零钱。

硬币问题的状态转移伪代码：

```java
DP(values, k) {
  res = MAX
  for c in values
    // 作出决策，找到需要硬币最少的那个结果
    res = min(res, 1 + DP(values, k - c))
    
  if res == MAX
    return -1
    
  return res
}
```

由此可以得出状态转移方程：

$$
F(n) =
\begin{cases}
0, n = 0 \\
-1, n < 0 \\
min\{1 + DP(n - c), c∈values\} \\
\end{cases}
$$

### 状态缓存与循环

动态规划的思想就是将递归自上向下的处理方向倒过来转换成**自下向上**，首先求出所有的子问题，然后通过底层的子问题向上求解更大的问题。

递归中的备忘录数组 `memo` 通常称之为DP数组（Dynamic Programming 的缩写）。依据状态转移方程的指导来**初始化状态**：

- 将 $F(0)$ 初始化成 $0$，即 `memo[0] = 0`
- 把 `memo` 中剩余的位置初始化成 $(k + 1)$ 即无穷大，便于后续**决策**时取最小值。

优化后的代码，时间复杂度为 $O(m*n)$：

```java
int getMinCounts(int k, int[] values) {
  int[] memo = new int[k + 1];
  memo[0] = 0;
  for (int i = 1; i < k + 1; i++) { memo[i] = k + 1; }
  for (int i = 1; i < k + 1; i++) {
    for (int coin: values) {
      if (i - coin < 0) { continue; }
      memo[i] = Math.min(memo[i], memo[i - coin] + 1);
    }
  }
  return memo[k] == k + 1 ? -1 : memo[k];
}
```

从理论上来说，带备忘录的递归算法与动态规划解法的时间复杂度是相同规模的，但是递归是依赖于函数调用的，每一次函数调用的代价非常高昂。此外递归本身的处理方式是**自上向下**的，因此每次都需要查询子问题是否被计算过。
