# Java：Map

## HashTable

**HashTable** 是早期 Java 类库中提供的一个哈希表实现，其本身是同步的，不支持 null 键和值，由于同步导致的性能开销，已经很少被推荐使用。

## HashMap

**HashMap** 是应用更加广泛的哈希表实现，行为大致与 HashTable 一致，区别在于它不是同步的，支持 null 键和值。通常情况下，get、put 操作可以达到 $O(1)$ 的时间性能，所以是绝大部分利用键值对存取场景的首选。

### 哈希算法

观察源码内对哈希值的计算，它并不是 key 本身的 hashCode，而是来自于 HashMap 内部的另一个 hash 方法。之所以需要将高位数据移位至低位进行异或运算，这是因为有些数据计算出的哈希值差异主要在高位，而 HashMap 里的哈希寻址是**忽略容量以上的高位**的，那么这种处理就可以有效避免类似情况下的哈希碰撞。

```java
(h = key.hashCode()) ^ (h >>> 16)
i = (capacity - 1) & hash
```

#### 双重验证机制

HashMap 的存储与检索依赖**双重验证机制**：

1. **定位桶**：通过 `key.hashCode() & (n - 1)` 计算桶索引
2. **桶内匹配**：在桶内遍历节点，通过 `equals()` 精确匹配对象

#### 如何正确重写 hashCode()

**自动组合字段哈希**：
```java
Objects.hash(name, age);
```

**31质数算法**：质数 31 进行位运算 `(31 * i = (i << 5) - i)` 且冲突率低

```java
@Override
public int hashCode() {
  int result = 17;
  result = 31 * result + name.hashCode();
  result = 31 * result + age;
  return result;
}
```

### 扩容

#### 触发条件

- 当元素数量 size > threshold（threshold = 容量×负载因子，默认为 16×0.75=12）时触发扩容。
- **例外**：链表长度 $\ge8$ 但数组容量 $<64$ 时，优先扩容而非树化。

#### 扩容核心步骤

1. **创建新数组**，新容量 = 旧容量 × 2（保持 2 的幂，如 16 -> 32）。
2. **数据迁移**（Rehash 优化）
   - 遍历旧数组的每个桶，根据 `e.hash & oldCap` 位运算将节点拆分为两类。
   - **低位链表**：`e.hash & oldCap == 0` -> 节点留在原索引位置 `newTab[j]`
   - **高位链表**：`e.hash & oldCap != 0` -> 节点移动到新索引位置 `newTab[j + oldCap]`
3. **处理链表/红黑树**
   - **链表**：拆分为高低位链表后，使用**尾插法**构建新链表，保持原顺序
   - **红黑树**：先拆分为链表，迁移后再根据长度决定是否树化或退化

### 树化

HashMap 的内部接口可以看作是数组 Node<K, V>[] table 和链表结合组成的复合结构，数组被分为一个个桶 bucket，通过哈希值决定了键值对在这个数组的寻址；哈希值相同的键值对，则以链表的形式存储。当链表的大小 $\ge$ 阈值（TREEIFY_THRESHOLD, 8），会发生**树化**。

**树化的本质原因**是**性能问题**，链表的查询是线性的 $O(n)$，会严重影响存取的性能。而树化能将时间复杂度降低至 $O(log(n))$。

当链表的大小 $\le6$ 时，树会重新退化为链表。

### HashMap 并发操作的具体风险

1. **数据覆盖**：JDK 8 采用**尾插法**避免了链表成环风险，但仍无法避免多线程同时 put 元素到同一空桶时可能产生的数据覆盖问题。
2. **size计数错误**：由于 `size++` 操作并非原子操作，多线程自增时会导致实际元素数量与 size 字段不一致。
3. **脏读**：在扩容过程中读取未迁移完成的旧桶时，可能返回 null 或部分数据。

### 线程安全解决方案

#### ConcurrentHashMap

**实现原理**：
- **锁颗粒度**：使用 `synchronized` 锁单个桶，非全局锁
- **读操作无锁**：利用 `volatile` 保证可见性，`get()` 操作无需加锁
- **并发扩容**：多线程协作迁移数据，线程执行 `put()` 时检测到扩容，可协助搬运数据

## TreeMap

**TreeMap** 是基于红黑树的一种提供顺序访问的 Map，和 HashMap 不同，它的 get、put、remove 之类的操作都是 $O(log(n))$ 的时间复杂度。
